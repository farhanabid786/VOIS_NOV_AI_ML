# Cardiovascular Risk Prediction — Deployment Package

**VOIS For Tech × AICTE | Farhan Abid**  
**Frontend:** React + Vite · **Backend:** FastAPI · **Deployed model:** Random Forest Classifier  
**Required local Python:** 3.10.x (target patch version: Python 3.10.14)

> Educational project only. This is not a medical device, clinical risk calculator, diagnosis, or substitute for professional care. The returned class score is not a calibrated clinical probability and must not guide treatment or medication decisions.

## 1. This package is aligned to the newly uploaded source files

- `Cardiovascular_Risk_Prediction.ipynb`
- `data_cardiovascular_risk.csv`
- `VOIS_FA_AIML.pptx`

The CSV has **3,390 rows and 17 columns**. The target is `TenYearCHD` (0/1). The deployed model uses the notebook's 13 final model features:

`age`, `education`, `sex`, `cigsPerDay`, `BPMeds`, `prevalentStroke`, `prevalentHyp`, `diabetes`, `totChol`, `BMI`, `heartRate`, `glucose`, `pulsePressure`.

The API accepts the raw inputs including systolic and diastolic blood pressure and derives `pulsePressure` using the notebook's transformations.

### Important model correction

The uploaded `.pkl` is an **XGBoost classifier**, not Random Forest. The notebook's final comparison table identifies Random Forest as selected, while its individually tuned Random Forest cell reports a different score. This package does not pretend the old XGBoost artifact is Random Forest.

Instead, it trains a new Random Forest model from the uploaded CSV and saves a complete preprocessing + classifier pipeline to:

`backend/models/random_forest_pipeline.joblib`

See `MODEL_ARTIFACT_AUDIT.md` for the audit trail.

## 2. Leakage-aware evaluation and artifact compatibility

The notebook applies SMOTE before the train/test split. That can leak information across the evaluation boundary and inflate results. This deployment uses a stratified 80/20 split first; imputation, notebook-aligned log transformations, feature engineering, scaling and SMOTE are fitted using the training partition only.

**Important:** Do not reuse a model binary generated under a different scikit-learn version. The model artifact is intentionally generated by `train_model.py` inside the Python 3.10 virtual environment after the pinned dependencies are installed. The authoring sandbox did not have a Python 3.10 interpreter, so the final binary is deliberately not pre-generated here; generate it locally in the target venv before pushing/deploying. This prevents shipping a pickle/joblib created under the current authoring runtime and then loading it under a different Python/scikit-learn environment.

When training completes in your Python 3.10 environment, it creates:
- `backend/models/random_forest_pipeline.joblib`
- `backend/models/evaluation_metrics.json`
- `backend/models/model_metadata.json`
- `backend/models/model_metadata.json`

The metrics file is the authoritative evaluation for the artifact you are deploying. It will contain the holdout metrics from your Python 3.10 run. Do not describe the notebook's 90.36% summary-table result as the deployment model's validated performance. Positive-class recall must be reviewed carefully; this is not a clinically validated model.

## 4. Windows setup — Python 3.10 virtual environment

### Step A — Install/check Python 3.10

Install Python **3.10.14 (64-bit)** if it is not already installed. During installation, enable the Python Launcher option.

Open PowerShell in the extracted project root and run:

```powershell
py -0p
```

Confirm that a Python 3.10 interpreter is listed. Then:

```powershell
cd backend
py -3.10 -m venv .venv
.\.venv\Scripts\Activate.ps1
python --version
```

The output must start with `Python 3.10`. If PowerShell blocks activation, run this once in the current terminal:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

### Optional one-command setup

From the project root, run:

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\setup_backend_windows.ps1
```

This creates `backend\\.venv` with Python 3.10, installs the pinned packages, trains the model from the CSV, and runs the API tests. It does not deploy anything.

### Step B — Install the pinned dependencies manually

Keep the backend virtual environment activated:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

Check versions:

```powershell
python -c "import sys, sklearn, imblearn, fastapi; print(sys.version); print('sklearn', sklearn.__version__); print('imblearn', imblearn.__version__); print('FastAPI', fastapi.__version__)"
```

Expected key versions: scikit-learn 1.5.2, imbalanced-learn 0.13.0, FastAPI 0.115.6.

### Step C — Retrain from the uploaded CSV (recommended verification)

Still inside `backend` with `.venv` active:

```powershell
python train_model.py
```

This reads `../data_cardiovascular_risk.csv`, runs a stratified holdout evaluation, and writes:
- `backend/models/random_forest_pipeline.joblib`
- `backend/models/evaluation_metrics.json`
- `backend/models/model_metadata.json`

The training script is deterministic (`random_state=10`). It uses the 300-tree Random Forest configuration recorded in the notebook. It also writes the Python, scikit-learn and imbalanced-learn versions into `model_metadata.json`.

After training, install the development test dependencies and run the API tests:

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest tests -q
```

Keep the backend virtual environment active for all these commands.

### Step D — Start the FastAPI backend

```powershell
python -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

Open these URLs:
- API status: http://127.0.0.1:8000/
- Health: http://127.0.0.1:8000/health
- Swagger test page: http://127.0.0.1:8000/docs

The health response must show:
- `status`: `healthy`
- `model_loaded`: `true`
- `model`: `RandomForestClassifier`

Do not proceed to frontend testing if the model health check is not healthy.

## 5. Run the React frontend

Open a **second** PowerShell window in the project root:

```powershell
cd frontend
Copy-Item .env.example .env
npm install
npm run dev
```

Open the Vite URL printed in the terminal, usually http://localhost:5173.

The local `.env` should contain:

```env
VITE_API_BASE_URL=http://127.0.0.1:8000
```

To create a production build locally:

```powershell
npm run build
```

The build output is `frontend/dist/`. Do not commit `node_modules/` or `dist/`.

## 6. Test one API prediction

With the backend running, open a new PowerShell terminal and run:

```powershell
$body = @{
  age = 48
  education = 2
  sex = "F"
  cigsPerDay = 0
  BPMeds = 0
  prevalentStroke = 0
  prevalentHyp = 0
  diabetes = 0
  totChol = 220
  sysBP = 120
  diaBP = 80
  BMI = 26.5
  heartRate = 75
  glucose = 85
} | ConvertTo-Json

Invoke-RestMethod -Uri "http://127.0.0.1:8000/predict" -Method Post -ContentType "application/json" -Body $body
```

The response contains the predicted class, two model output scores, threshold, model name/version and disclaimer. Scores are not calibrated clinical probabilities.


### What must and must not be pushed

**Push:** source code, notebook, CSV, README, presentation, requirements, and the `.joblib` model + evaluation/metadata JSON generated inside the Python 3.10 virtual environment.

**Never push:** `.venv/`, `node_modules/`, `.env`, API keys, passwords, local cache folders. The supplied `.gitignore` excludes these.

The model artifact must be present in `backend/models/` before deploying. If GitHub rejects it due to file size, check the actual file size and use Git LFS rather than silently removing the model. Never upload a `.joblib` generated under a different scikit-learn version than the pinned environment.

## 8. Deploy FastAPI to Render

1. Sign in to Render and choose **New → Blueprint**.
2. Connect the GitHub repository you just pushed.
3. Render reads the root `render.yaml`.
4. Verify the service settings:
   - Root directory: `backend`
   - Build command: `pip install -r requirements.txt`
   - Start command: `uvicorn main:app --host 0.0.0.0 --port $PORT`
   - Health check: `/health`
   - Python version: `3.10.14`
5. Deploy and wait for the service to become Live.
6. Test `https://YOUR-RENDER-SERVICE.onrender.com/health` and `/docs`.

If configuring manually instead of Blueprint, use the same settings. Do not set the root directory to the repository root; the backend service root is `backend`.

## 9. Deploy React to Vercel

1. In Vercel, import the same GitHub repository.
2. Set Root Directory to `frontend`.
3. Framework preset: **Vite**.
4. Add environment variable:
   - Name: `VITE_API_BASE_URL`
   - Value: `https://YOUR-RENDER-SERVICE.onrender.com`
   - Do not add a trailing slash.
5. Deploy.
6. After Vercel provides the production domain, return to Render and set:
   - `FRONTEND_ORIGINS` = `https://YOUR-PROJECT.vercel.app`
7. Redeploy/restart the Render backend.
8. Test the deployed frontend form and verify the browser Network tab shows a successful `POST /predict`.

Whenever `VITE_API_BASE_URL` changes, trigger a new Vercel build because Vite embeds this value during build time.

## 11. Common problems

- **`py -3.10` not found:** install Python 3.10 x64 and confirm it appears in `py -0p`.
- **PowerShell activation blocked:** use the process-scoped execution policy command above.
- **`ModuleNotFoundError`:** activate `backend\.venv` and install `backend/requirements.txt` again.
- **Health says `model_not_found`:** run `python train_model.py` from the backend directory.
- **Frontend cannot connect:** check backend `/health`, `.env` URL and CORS `FRONTEND_ORIGINS`.
- **Vercel still calls old API:** update `VITE_API_BASE_URL` and redeploy.
- **Render deploy fails:** check that Render's root directory is `backend` and its Python version is 3.10.14.
